# Lattice agent contract

Build the complete [v0.1 brief](docs/design/brief-v0.1.md) in L0 → L1 → L2 → L3 → L4 → L5 order. Work in this repository (`~/lattice`). Continue safe, authorized work without permission handoffs.

- The graph/query/cache/CLI/viewer/MCP layers are domain-neutral. Domain names, classifications, interpretations, and display text belong in lenses under `examples/` or a consumer repository's `.lattice/lens.yaml`.
- Never copy Graft implementation. Import its optional graph only through a documented, validated adapter; otherwise use the file/module adapter.
- Never commit or push to Charter & Kin / `hyunlord/feudal-lord-simulator`. Read-only source, external cache/output, example lens here.
- Modify bs-mobile through an issue and PR only. Do not commit directly to its main or modify its design originals. Do not resume held device work.
- Keep the numerical prototype oracle distinct from evidence about code dispatch and runtime behavior. Four base-data forms and ten profile forms can coexist with explicit source labels.
- All acceptance requirements are tracked in [the ledger](docs/review/acceptance.md). Missing evidence is pending, never pass. Same graph/findings feed web and MCP.
- Before viewer implementation, follow [viewer design](docs/design/viewer.md). No domain-specific screens, prototype layout copying, external fonts, or runtime CDN assets.
- Do not add unrequested dependencies. The CLI/TypeScript/npm packaging required by the brief is authorized; document exact dependency necessity before adopting any additional parser/SDK/UI package. No new framework by default.
- Use short issue-linked branches and PRs. Commit titles state intent with Conventional Commits; optional Lore trailers record actual verification and gaps. Do not amend other work.
- Run meaningful tests, formatting, typecheck, and CI before merging. Visually exercise the real viewer; stdio probes alone do not prove agent integration.
- Report each milestone in Korean, first line `관문: 통과/실패/부분 — ...`, at most ten summary lines plus commit/PR/CI links. At L2 completion put the working bs-mobile Pages link first. Never call L2 complete while the URL is unavailable.
- No evidence ZIPs/CRCs/receipts. Use source, concise reports, CI logs, screenshot artifacts, and direct links.
