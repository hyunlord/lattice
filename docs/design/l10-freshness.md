# L10 resident query and freshness state

MCP retains indexes only for the immutable graph object belonging to one verified source generation. Layer scopes, incident edges, node identities and overview facet distributions are resident. A rebuild replaces the graph object; old indexes become unreachable. The logic query index follows the same generation boundary. No time-to-live or watcher event is evidence of freshness.

`freshness.mode: content-hash` describes the graph's binding to previously read source bytes. `freshness.observationMode` separately reports whether the current observation uses `content-hash` reads or `metadata-witness` reuse. The latter does **not** claim that all bytes were rehashed on this request.

On local APFS, ext and Btrfs, previously verified bytes may be reused only when bigint device, inode, size, mtime and ctime match. Restoring mtime does not restore ctime. Initial reads verify the opened descriptor before and after hashing; path identity is checked again afterward. Every source observation rereads the Git inventory and repository metadata, checks each selected file, and verifies all observed file identities again after the inventory comparison. New paths, removals, inode replacements, same-size writes with restored mtime, and edits during observation therefore invalidate the observation or require new bytes. Each observation verifies unique parent-directory real paths and rechecks them at the end; symbolic-link files also recheck containment before reuse. Final source witnesses compare both the leaf lstat identity and the followed target identity, so retargeting a link to a preexisting hardlink cannot bypass the end-of-observation check. Unchanged dangling links remain absent; newly appearing targets invalidate the observation. Changed files undergo real-path containment checking before reading. Lens, note and draft text reads have pre/post/final identity witnesses; absent, nonfile and oversized selected paths retain final observation witnesses. Concurrent observations share verified byte records but keep separate verification sets. No unresolved path is read from outside the repository. A missing input follows existing missing-file handling; changes during a scan fail closed and the next query retries.

Unknown filesystems, cross-device source files and coarse whole-second ctime values use full byte reads. Artifact files also have an initial full digest, descriptor and path checks, and the same local-filesystem witness constraints. These are ordinary local-filesystem guarantees, not protection against a privileged process forging filesystem metadata or a filesystem that misreports its type/change times. Remote filesystems never use the fast path. Synchronous builds and historical observations retain their full-content path.

## Profiling evidence

On the frozen large L9 source tree, Node25.8.2/macOS, an unchanged full observation took7509ms, including4692ms in49,528 synchronous file reads and846ms in49,606 real-path resolutions. A separate run took8557ms. This is source observation alone, excluding graph artifact verification, query work and response serialization.

A preliminary witness implementation took3976ms cold and1934/2434ms warm. Resolving containment only when reading new bytes reduced preliminary warm observations to1152/1265/1702ms. These intermediate figures precede the final cross-observation identity pass and are **not** the thirty-request MCP p95 acceptance measurement. The final cross-observation pass measured1332/1253/1230ms for source observation alone. A CPU profile attributed most remaining time to Git subprocess waits and metadata checks. Omitting the redundant immediate post-stat for cached bytes while retaining the final global pass subsequently measured1013/973/973ms; cold was6812ms during concurrent development. Subsequent alias/configuration/absence race fixes add containment checks; these intermediate numbers do not establish the one-second gate. The final all-repository client timings remain required.

Regression coverage includes same-size/restored-mtime source and artifact edits, path replacement and deletion, invalid lens failure/recovery, concurrent cold build-once, graph/presentation generation invalidation, and source changes both during byte reads and after an individual file was observed. Existing source additions/removals remain covered by the MCP integration test.
