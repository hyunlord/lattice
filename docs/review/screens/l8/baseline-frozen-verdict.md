# 첫 화면 이해도 판정: 1.png(zod)와 2.png(AutoMapper)

두 그림만 보고 판정했고, 다른 파일은 열지 않았습니다. 그림 상단 범례는 "위가 아래를 사용"이라고 되어 있어서 화살표를 그 뜻으로 읽었습니다.

---

## 1.png — zod 지도

**① 무엇을 하는 저장소인가**
TypeScript용 스키마 검증 라이브러리이고, 정적 타입 추론을 해 줍니다(부제 기준). 소스 루트는 `packages/zod/src`입니다.

**② 핵심 덩어리 3개와 역할**
1. **v4** (파일 106개, 하위 폴더 4개): 가장 아래에 있는 큰 덩어리로, 이름과 크기로 보아 현재 주력 구현으로 보입니다. 하위 폴더 4개의 이름과 역할은 화면에 없어서 **모릅니다**.
2. **v3 연결 묶음** (v3 6개, v3/helpers 6개, v3/locales 1개): 서로를 참조하는 순환 묶음입니다. 이전 버전 구현으로 짐작하지만 세 폴더 모두 "역할 설명 없음"이라 **확인은 안 됩니다**.
3. **진입용 작은 폴더들** (루트 2개, locales 1개, mini 1개, v4-mini 1개): 파일이 1~2개뿐이라 v4를 다시 내보내는 진입점으로 짐작합니다. 역할 설명은 없습니다. "탐색 시작"은 루트에만 표시되어 있습니다.

**③ 무엇이 무엇을 쓰는가**
- 루트, locales, mini, v4-mini가 각각 **v4를 사용**합니다. 사용 파일 수는 2·1·1·1입니다.
- v3 묶음 안에서는 v3, helpers, locales가 서로를 사용합니다(정적 참조 순환).
- v3 묶음과 다른 덩어리를 잇는 화살표는 없습니다. "생략한 외부 화살표 0개"라고 되어 있으니 화면에 보이는 것이 전부일 것입니다.

**점수: 3/5**
- **이유:** 목적이 즉시 보이고, "작은 진입점들 → v4" 방향과 v3 순환 묶음이라는 큰 구조가 30초 안에 잡힙니다.
- **모호한 부분:**
  - 모든 덩어리가 "역할 설명 없음"이라 역할은 이름을 보고 추측한 것입니다.
  - v4의 하위 폴더 4개가 펼쳐져 있지 않습니다. 파일 106개가 한 상자에 들어 있어 핵심 내부를 알 수 없습니다.
  - v3 묶음을 아무도 쓰지 않는 것처럼 보이는데, 정말 고립된 것인지 표시가 빠진 것인지 판단할 수 없습니다.
  - 루트 locales와 v3/locales, mini와 v4-mini의 차이를 모릅니다.

## 2.png — AutoMapper 지도

**① 무엇을 하는 저장소인가**
한 객체를 다른 객체로 옮겨 담는 매핑 코드를 없애 주는 라이브러리입니다(부제 기준). 소스 루트는 `src/AutoMapper`입니다. 사용 언어는 화면에 나오지 않습니다.

**② 핵심 덩어리 3개와 역할**
1. **연결 묶음 (폴더 6개)**: 루트 12, Configuration 17, Execution 4, Internal 9, Mappers 19, QueryableExtensions 8개 파일로, 사실상 제품 코드 대부분입니다. 역할은 모두 "역할 설명 없음"입니다. 이름으로 짐작하면 설정, 실행, 내부 유틸, 타입별 매퍼, 쿼리(IQueryable) 확장입니다.
2. **Licensing** (파일 6개): 라이선스 처리로 짐작합니다. Configuration이 사용합니다.
3. **ApiCompat**(1개)와 **Configuration/Annotations**(10개): 둘 다 "표시 범위의 명시 import 연결 없음"으로 나옵니다. 따로 떨어진 덩어리들인데 역할은 **모릅니다**. Annotations는 속성(attribute) 정의일 것으로 추측만 합니다.

**③ 무엇이 무엇을 쓰는가**
- 묶음 바깥: **Configuration이 Licensing을 사용**합니다(1개 파일). 화면의 유일한 외부 화살표입니다.
- 묶음 내부(16방향):
  - 루트는 Configuration과 Internal을 사용합니다.
  - Configuration은 루트, Mappers, QueryableExtensions, Execution을 사용합니다.
  - Execution은 루트와 Internal을 사용합니다.
  - Internal은 루트, QueryableExtensions, Configuration, Mappers를 사용합니다.
  - Mappers는 루트, Execution, Internal을 사용합니다.
  - QueryableExtensions는 루트를 사용합니다.
- 결국 6개 폴더가 거의 모두 서로를 쓰고 있어서 위아래 순서가 없습니다.

**점수: 3/5 (낮은 3)**
- **이유:** 목적은 명확합니다. 덩어리 목록과 Configuration → Licensing이라는 의존 하나는 확실히 읽힙니다.
- **모호한 부분:**
  - 핵심 코드 전체가 하나의 순환 묶음에 들어 있습니다. "중심이 어디고 흐름이 어느 방향인가"가 보이지 않고, 표가 빽빽해서 30초 안에 소화하기 어렵습니다.
  - 모든 폴더가 "역할 설명 없음"입니다.
  - "import 연결 없음"이 정말 독립적이라는 뜻인지, 같은 네임스페이스라서 import가 필요 없는 것인지 구분되지 않습니다.
  - Configuration과 Configuration/Annotations가 왜 따로 표시되는지 모릅니다.
  - 매핑 요청이 어디서 들어와 어디로 흐르는지 알 수 없습니다.
