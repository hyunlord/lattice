# C# and Rust static imports

L7 extends the existing zero-configuration code adapter: `.cs` and `.rs` files were already discovered, and now produce static `imports` edges rather than file-only nodes. No dependency, repository execution, compiler or build system is needed. These edges describe source declarations, not runtime calls or implemented behavior.

C# joins explicit `using` directives to selected source namespace/type declarations. Block, nested and file-scoped namespaces, namespace aliases, type aliases, `global using`, `global::` and `using static` are supported. A namespace can legitimately contribute several files, so its import fans out to all selected declarations; type ambiguity remains a diagnostic. A global directive is represented at its authored file and line, not multiplied into implicit imports for every compilation unit. Resource-disposal `using` statements and literal/comment contents are excluded.

Rust supports conventional `lib.rs`/`main.rs`, `name.rs`/`name/mod.rs`, explicit `mod` declarations, inline modules, `use` trees (groups, aliases and globs), and `crate`/`self`/`super` paths. A selected file alone does not establish module membership: declared module paths must connect it. Nested block comments, raw strings, character/string literals, lifetimes and macro token groups do not create false imports. A use of an item in a known module records that source-module dependency; it does not prove item visibility, re-export identity or compiler resolution. Root-level items require an explicit source declaration.

Unresolved external names, missing local modules and ambiguous candidate files retain statement-line diagnostics. `#[path]` modules are explicitly unresolved instead of guessing the conventional file. C# project/assembly references, implicit SDK usings, extern aliases, generic/tuple aliases and nested type imports are not compiler-resolved. Rust Cargo target selection, external-crate aliases, macro expansion, generated modules, re-exports and conditional-compilation evaluation are not implemented. Declarations in conditional branches remain static source evidence. These limitations do not claim execution or fabricate substitute nodes.

Focused verification covers C# namespace fan-out and static/alias/scoped imports; Rust grouped paths, inline scopes, root items and ambiguity; ignored strings/comments/macros; missing/custom-path modules; and cold-to-cached module metadata equality. Existing JavaScript/TypeScript/Python extraction remains on its existing lexer/resolver path.

Primary grammar references, checked 2026-10-10: [C# using directives](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/using-directive), [Rust use declarations](https://doc.rust-lang.org/reference/items/use-declarations.html), [Rust modules](https://doc.rust-lang.org/reference/items/modules.html).
